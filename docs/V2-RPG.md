# LifeRPG v2 — 4단계 RPG 게임 흐름

2026-10-15 · 구현 및 합성 검증. 이 단계의 실제 OpenAI 요청은 **0회**다. 운영 DB, 기존 유료 합성 DB/비용 장부, 배포는 변경하지 않았다. 기본 모델 `gpt-6.1-sol`, reasoning `medium`, 기존 토큰 한도·단가·예산 로직을 유지한다.

이후 5단계에서 전체 세계/출처 원문 전송을 관련 문맥 선택으로 바꾸고 저장 엔티티 한도를 확장했다. 최신 기억·요약 계약과 문맥 한도 동작은 [V2-MEMORY.md](V2-MEMORY.md)를 따른다. 아래의 200개/전체 읽기 기반 문맥 제약과 검증 수치는 4단계 완료 시점 기록이다.

## 구현 구조

기존 `service → 영속 job → GM adapter → worker → 원자적 commit` 경로에 서버 내부 RPG 계약과 실행기를 추가했다. MCP 도구는 기존 5개이며 입력 계약도 유지한다. 버디는 `interact_with_gm(kind: action, message: ...)`로 자연어 행동만 보낸다. XP·인벤토리·게임 patch를 직접 전달할 수 없다.

| 구성 | 역할 |
| --- | --- |
| `src/v2/rpg-contracts.ts` | GM 전용 Zod 계약: 콘텐츠, 작업, 공개 장면 |
| `src/v2/rpg.ts` | 소유권·버전·관계·보상 검증, 상태 변경, 공개 투영 |
| `src/v2/worker.ts` | 현재 RPG와 비공개 기억 전달, 기존 예약/정산/lease/fencing, 검증 후 확정 |
| `src/v2/openai-gm.ts` | 같은 Responses adapter에 확장된 strict Structured Outputs 적용 |
| `migrations/v2/003-rpg.sql` | 현재 엔티티, 삭제 가능한 버전 이력, 세계 보상 청구, 세계 시간 |

엔티티는 자유 텍스트를 담되 **타입별 닫힌 구조**를 따른다. SQL, 실행 코드, 임의 JSON patch는 허용하지 않는다. GM은 다음 콘텐츠를 자유롭게 만들고 기존 정의를 참조한다.

| 기능 | 확정되는 상태 |
| --- | --- |
| 탄생·성장 | 소유자당 캐릭터 하나, GM이 결정한 레벨·기본 능력치·직업·현재 장소, 별도 XP ledger |
| 직업·스킬·특성·칭호·업적 | 자유로운 이름·설명·수치 효과의 정의, 정의 버전에 고정된 보유 상태 |
| 아이템·장비 | 획득·소모·상실 수량, 장착 슬롯, 기본 능력치와 효과를 합산한 유효 능력치 |
| 퀘스트 | 제안 → 진행 → 완료 또는 실패, 진행도·목표·장소, 완료 보상 한 번 |
| 세계 | NPC·장소·세력·관계·세계 사건, 부모/참가자 참조, 명시적 세계 시간 진행 |
| 서사 | 공개 장면·대사·선택지, 비공개 엔티티/메모·세계 기억·GM 성찰 |
| 재검토 | 판정 이의 제기의 증분 보정, 삭제/정정 후 허구로 재해석 |

고정 직업 목록, 활동별 XP 표, 강제 레벨 곡선은 없다. 레벨과 능력치의 의미는 GM의 판단이다. 서버는 정수 범위·음수 XP·참조·장착·중복 보상을 검증한다. 스킬의 특수한 효과는 서술할 수 있지만 현재 자동 계산기는 이름별 정수 능력치 가산만 실행한다. 아이템 사용 효과는 GM이 소비와 캐릭터 변경을 같은 판정으로 제안한다.

## GM 내부 판정 계약

기존 `outcome / summary / xp_delta / question / memories`에 다음을 추가했다. OpenAI wire에서는 모든 필드가 required이며 미사용 선택값은 `null`이다. `summary`는 공개 영수증에 쓰지 않는 초안이다.

- `operations`: 최대 32개. `put`, `inventory`, `equip`, `retire`, `advance_time`, `resolve_reinterpretation`.
- `reward_source`: 독립 세계 보상의 완료 퀘스트 또는 해결된 세계 사건 ID. 보상 수령 후 소모해도 같은 source로 다시 지급하지 않는다.
- `scene`: 공개 판타지의 제목·본문·대사·선택지. 숨은 복선은 이 필드에 넣지 않는다.

`put`은 새로운 정의/세계 엔티티 생성과 기존 버전 교체에 사용한다. 신규 ID는 `@alias`와 `expected_version: 0`, 기존 엔티티는 서버 UUID와 정확한 버전을 사용한다. 서버가 alias를 UUID로 변환한다. 같은 묶음의 앞선 작업에서 바뀐 버전을 다음 작업이 참조할 수 있다. 인벤토리 정의는 획득 작업보다 먼저 생성해야 한다.

`inventory`는 정의와 보유 수량의 증분을 받는다. 아이템은 최대 1,000,000개, 나머지 보유 인스턴스는 0~1개다. 장비는 여러 인스턴스를 가질 수 있지만 한 슬롯에는 하나만 장착할 수 있다. 같은 직업·스킬·특성·칭호·업적의 중복 활성 보유는 거부한다. 직업은 실제로 보유해야 선택할 수 있다. 직업 효과는 선택한 직업에, 장비 효과는 장착한 장비에만 적용된다.

보유 중인 정의의 몰래 변경은 거부한다. 변경하려면 기존 보유 상태를 명시적으로 제거하고 후속 정의를 만들거나, 별도 정의로 전환한다. 버전 자동 재연결은 구현하지 않았다. 퀘스트는 `offered → active → completed`, `offered/active → failed` 전이를 지원하고 완료·실패 후 다시 열 수 없다. 반복 모험은 새로운 퀘스트 엔티티로 표현한다.

`clarify`와 `no_change`는 XP·기억·작업·장면을 함께 변경할 수 없다. 탄생은 캐릭터가 있어야 확정되고 시작 XP는 0이다. 여러 차례 질문해도 원래 시작/행동/관찰/이의 제기 의도와 질문 이력이 이어지며, 이전 요청 조회도 최신 질문/최종 영수증을 가리킨다. 질문 체인은 8단계까지다.

## 원자성과 중복 방지

모든 작업을 메모리상의 후보 상태에 먼저 적용하고 전체 참조 그래프를 검증한다. 검증을 통과하면 엔티티·버전 이력·XP·세계 시간·세계 보상 청구·기억·판정·영수증·job 완료를 같은 DB 트랜잭션으로 저장한다. DB 오류도 전체 게임 변경을 되돌린다. **API 사용량 정산은 기존처럼 별도 선행 트랜잭션에 남는다.**

검증에는 소유자 경계, 정확한 버전, 불변 타입, 살아 있는 참조, 장소/세력 부모 순환, 공개→비공개 참조 금지, 장착 슬롯 충돌, 보유 정의 버전, 퀘스트 전이·진행도, 정수 범위가 포함된다. 퇴장시키는 엔티티를 참조하는 관계도 같은 판정에서 정리해야 한다.

기존 request key, 사건 fingerprint, 현실 사건의 기본 보상 entitlement를 재사용한다. 독립 세계 행동의 양의 보상은 완료 퀘스트/해결된 세계 사건에 귀속하고 `rpg_reward_claims(owner_id, source_id)`로 한 번만 청구한다. 이의 제기는 기존 판정 체인의 새 head에서 증분 보정을 적용한다. 복제된 새 UUID가 의미상 같은 사건인지까지 서버가 판별하는 것은 아니다. 이 의미 판단은 GM과 향후 품질 평가의 범위다.

## 공개 결과와 현실 접수

현실 사건을 저장할지 결정하는 주체는 서비스다. GM 입력의 `reality.status: recorded`는 **보고가 서버에 저장되었다는 뜻이며 독립적인 사실 검증 표시가 아니다.** `confirmed_new_report`는 삭제 후 새로운 명시적 보고를 허용하는 접수 정책용 플래그다. GM 입력과 질문 이력에는 이 플래그를 전달하지 않는다.

요청 결과는 다음처럼 책임을 나눈다.

- `reality`: 서버가 현재 저장 상태에서 계산하는 `recorded / corrected / deleted / not_applicable`와 살아 있는 사건 ID.
- `player_result.summary`: 서버가 작성하는 확정/변경 없음 안내. GM 초안이 “기록하지 않았다”라고 해도 이 문장은 영수증에 포함하지 않는다.
- `player_result.changes`: 실제 반영된 XP 증분·잔액 및 공개 엔티티의 버전/확정 상태. 비공개로 전환된 기존 공개 엔티티는 `removed: true, state: null`로 표시한다.
- `player_result.fiction`: GM의 공개 판타지 장면·대사·선택지. 선택지는 아직 실행된 결과가 아니며 새 `action` 요청으로 처리한다.
- `world_tick / effective_stats`: 서버가 확정한 세계 시각과 능력치.

`read_liferpg(view: game)`은 공개 엔티티만 돌려준다. 비공개 기억·정체성·엔티티·private_notes를 그대로 반환하지 않는다. 삭제로 끊어진 참조의 종속 공개 투영도 숨긴다. 카드 UI 구현은 추가하지 않았으며 버디가 이 구조로 연출할 수 있다.

구조 분리와 서버 숫자/영수증은 결정적으로 검증한다. 다만 LLM이 자유로운 공개 문장에 비공개 의미를 옮기거나 판타지 문장에서 잘못된 주장을 하는 문제를 JSON Schema만으로 완전히 막을 수는 없다. 헌장의 공개/비공개 규칙과 합성 회귀를 적용했고, 실제 모델의 장면 품질·비밀 준수 평가는 별도 승인 후 필요하다.

## 삭제와 재해석

모델에 실제 전달한 RPG 공개/비공개 payload, 기억, 사건, 이전 판정, 질문 이력의 출처를 합쳐 모든 새 파생물에 상속한다. `rpg_versions`도 삭제 가능한 payload만 참조한다. 현실 기록 삭제/정정 시 관련 현재 상태와 과거 버전 텍스트를 지우고, RPG 엔티티에는 중립 ID·종류·버전과 `needs_reinterpretation`만 남긴다. 삭제된 내용은 새 GM 문맥에서 제외된다.

GM은 이후 `action`에서 빈 껍데기를 새로운 허구로 대체하거나 퇴장시키고, XP·아이템을 유지/조정하고, `resolve_reinterpretation`으로 기존 판정의 재검토 표시를 해소할 수 있다. 기존 출처가 없는 허구로만 복원하며 삭제된 현실을 다시 추론해 쓰도록 요청하지 않는다. 새 복구 상태도 읽은 현재 문맥의 출처를 상속한다. 판정 재검토 수와 미복구 엔티티 수는 별도 상태이므로 하나를 해소했다고 모두 복구되었다고 표시하지 않는다.

삭제의 privacy epoch, 진행 중 응답 폐기, 별도 삭제 manifest를 통한 과거 백업 복원 보호를 그대로 사용한다. 이 구현은 보수적으로 전체 읽은 문맥의 출처를 상속하므로 한 사건 삭제가 넓은 영역의 세계를 무효화할 수 있다. 세밀한 기억 선택과 문맥 축소는 다음 단계다.

## 한도·호환성·실행

- 플레이어당 최대 200개 엔티티(퇴장 이력 포함), 판정당 32개 작업, 문맥 출처 50건, worker 문맥 48,000자. 크기를 넘기면 유료 호출 전에 또는 상태 확정 전에 거부한다.
- OpenAI 기본 입력 예약 상한 16,384, 출력 2,048은 그대로다. UTF-8 byte 기반의 보수적 사전 검사에는 JSON schema·헌장·프레이밍도 포함되므로 **RPG 상태가 커지면 200개보다 훨씬 앞서 `context_limit`에 도달할 수 있다.** 자동 누락·토큰 상한/예산 증가는 하지 않는다. 큰 탄생은 짧은 초기 상태와 후속 턴으로 나눠야 한다.
- 최소 2개 엔티티의 탄생 → 독립 세계 보상은 기본 설정의 주입 전송 계층으로 통과했다. 풍부한 14개 작업 탄생과 전체 캠페인은 mock 판정으로 검증했다. 실제 모델이 같은 계약을 얼마나 안정적으로 생성하는지는 이번 무과금 검증으로 확정하지 않는다.
- 새 `003-rpg.sql`은 테이블/세계 시간만 추가하며 기존 ledger를 재작성하지 않는다. 로컬 mock과 승인된 합성 실행기의 bootstrap에 연결했다. 이번에는 새 임시 테스트 DB에만 적용했다.
- 이전 단계의 초기화 완료 상태를 새 캐릭터로 자동 재창작하거나 과거 영수증을 다시 실행하지 않는다. 기존 유료 합성 DB는 1~3단계 실험 증거로 보존했다. 이후 모델 품질 시험은 명시적으로 승인한 새 격리 시나리오/예산으로 준비해야 한다.
- `dev:v2`는 계속 mock이며 운영 Vercel entry와 기존 웹사이트는 v1이다. 실제 GM 연결은 기존 승인 gate가 있는 adapter/합성 runner에만 있다. 무접속 주기 실행은 추가하지 않았다.

```sh
npm run test:v2:rpg       # RPG 합성 시나리오, 실제 API 없음
npm run test:v2           # 기반 + 로컬 HTTP + OpenAI 가짜 전송 + RPG
npm run test:v2:postgres  # .local/pg-runtime의 로컬 PG 바이너리로 임시 DB 생성
npm test                 # v1 및 v2 전체 회귀
npm run build
```

## 검증과 다음 단계

최종 검증: `npm test` **160/160**, `npm run test:v2` **54/54**(RPG 24개 포함), `npm run test:v2:postgres` **7/7**, `npm run build` 및 TypeScript 검사 통과. `git diff --check`도 통과했다. 이 수치는 서로 포함 관계가 있으므로 합산하지 않는다.

RPG 회귀는 탄생·자유 직업/스킬/특성/칭호/업적·성장·장비 효과·획득/소모/상실·퀘스트 완료/실패·독립 세계 보상·관계 변화·질문 연속·이의 제기·공개/비공개 분리·삭제·백업 복원·실패 원자성을 다룬다. 실제 PostgreSQL 다중 연결에서는 lease 경합, 늦은 응답, 삭제 경합, 세계 보상 중복 청구와 전역 예산 잠금을 확인한다. 검증은 모두 합성 데이터이며 OpenAI 전송 테스트는 주입한 가짜 응답이다.
