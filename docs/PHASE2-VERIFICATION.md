# GM 판정과 캐릭터 성장 2단계 검증

2026-10-14 · Asia/Seoul · 로컬 구현 검증

GM 판정으로 XP와 6대 기본 스탯을 변경하고 고정 growth-v1 레벨을 계산하는 엔진을 추가했다. 실제 계약은 [SPEC.md](../SPEC.md), 전체 방향은 [DESIGN.md](../DESIGN.md)를 따른다. 이번 단계에는 퀘스트·NPC·세계·장비·스킬·웹 UI가 없다.

PGlite의 별도 메모리 인스턴스에서 합성 사건·캐릭터만 사용했다. .env.local이나 운영 Neon DB에 연결하지 않았다. 테스트 플래그는 테스트 config에서만 활성화했고 운영 설정은 변경하지 않았다. 운영 migration·원격 smoke·Vercel 배포·실제 캐릭터/세계 생성·수다방 프로젝트 지침 변경은 수행하지 않았다.

## 미검증 사항과 제약

PGlite는 한 인스턴스의 트랜잭션을 직렬화한다. 동시에 제출한 요청의 버전 판정과 중복 방지는 검증했지만 여러 PostgreSQL 세션의 잠금 경합·대기 timeout·Vercel 인스턴스 경쟁은 실제 재현하지 않았다. 운영 적용 전 격리된 Neon branch에서 실제 001→002→003 migration과 독립 연결 경쟁을 확인해야 한다. 실제 수다방에서 새 GM 도구의 제공·자율 선택·결과 발표도 아직 검증하지 않았다.

서버는 보상량과 사건의 의미를 정하지 않는다. 다른 aspect_key나 그룹 키로 같은 의미의 보상을 요청하는 행위는 자동 검출하지 않는다. GM은 기존 판정을 조회하고 안정된 주제·항목을 재사용해야 한다. 판정 정정은 보정 delta이며 전체 과거 보상을 자동 재산정하지 않는다. 합성 게임은 test 사건만 사용하고 실제 사용자 캐릭터 초기 생성은 차단되어 있다.

본문 한도 16 KiB, 요청당 판정 최대 10개·판정당 사건 최대 20개를 유지한다. 여러 요청으로 나누면 각 요청만 원자적이다. 게임 맥락은 최근 판정 10개를 제공하며 과거 판정·근거는 필터와 페이지로 추가 조회한다. 변경 영수증은 저장 당시 결과이며 현재 상태를 대체하지 않는다.

운영 적용은 별도 승인 후 데이터 백업·격리 검증·코드와 migration 전환 계획을 확인해서 진행한다. 003은 새 GM 도구에 필요하며 자체적으로 캐릭터를 생성하지 않는다. 구버전 코드와 새 코드의 사건 쓰기를 혼용하지 않는 1단계 전환 조건도 계속 적용한다.
