# LifeRPG v2 — 5단계 장기 기억과 성장하는 GM

2026-10-15 · 요청된 장기 기억 범위 구현 및 무과금 합성 검증. 새 유료 OpenAI 요청, 기존 유료 합성 DB/비용 장부 변경, 운영 DB 변경, 배포는 하지 않았다. MCP 5개와 공개 결과 계약, `gpt-6.1-sol` / reasoning `medium`, 기존 토큰·예산·가격 설정을 유지한다. 별도 벡터 DB, 임베딩 호출, 에이전트 프레임워크, 화면 개편은 추가하지 않았다.

## 이번 변경의 핵심

4단계에서는 현재 세계 전체와 최근 기억 20개를 읽고, 그 출처의 현실 사건 원문을 모두 다시 전송했다. 5단계에서는 **현재 판정에 보여줄 내용**과 **삭제·정정 검증에 필요한 출처 집합**을 분리한다. 요약이 현실 사건 60건에 의존해도 모델에는 요약을 보내고 서버는 60건의 출처·버전을 별도로 보존한다.

| 파일 | 역할 |
| --- | --- |
| `src/v2/context.ts` | DB 검색·중요도·관련성·현재 장면을 이용한 문맥 선택, 요청 크기 검사 |
| `src/v2/memory-contracts.ts` | 기억 종류·정보 성격·중요도·복선·출처·개정 계약 |
| `src/v2/memory.ts` | 요약/성찰 저장, 정체성 개정, 기억 원본 관계 보존 |
| `src/v2/worker.ts` | 선택 문맥 manifest, 출처 버전 검증, 게임+기억 원자적 확정 |
| `migrations/v2/004-memory.sql` | 기억 분류/중요도/미해결 표시, 이전 정체성, 기억 출처 그래프 |

## 선택과 문맥 상한

필수 문맥은 현재 요청, 해당 현실 보고, 질문 이력, 이의 제기 대상 판정, 현재 GM 정체성, 캐릭터와 현재 장소/직업/장착 참조, 입력에서 이름·ID로 명시한 엔티티/기억이다. 유효 능력치 합계도 서버의 실제 상태에서 계산한다. 필수 엔티티의 참조를 함께 가져와, 장소·정의·보유 버전을 근거 없이 바꾸지 않게 한다.

나머지는 기억의 중요도·정설 여부·미해결 복선·문자열 관련성·엔티티 연결·최근성을 점수화한다. 활성 퀘스트, 현재 장소의 NPC, 비공개 세계 사건도 우선 후보가 된다. 소유자와 삭제 필터를 먼저 적용하고 기억 후보는 최대 160개로 제한한다. 요약을 선택하면 그 원본은 일반적인 문맥에서 중복해서 넣지 않는다. 명시적으로 요청한 기억 ID는 원본도 다시 선택할 수 있다.

각 후보를 추가할 때 **실제 OpenAI 요청과 동일한 크기 검사**를 수행한다. 낮은 우선순위 후보가 넘치면 제외하고 `context_omissions`에 개수를 남긴다. `attempts.context_manifest`에는 정책 `memory-v1`, 선택한 기억/엔티티/payload ID, 생략 수, 문맥 JSON 바이트, 모든 현실 출처 버전을 기록한다. 생략 수는 내부 GM 문맥과 감사 메타데이터이며 버디에게 비공개 기억 목록을 반환하지 않는다.

핵심 정보만으로도 한도를 넘으면 `required_context_limit`으로 **예약과 모델 호출 전에 중단**한다. 근거를 잘라 성공으로 처리하지 않는다. 기존 OpenAI 입력 한도 16,384, 출력 2,048, UTF-8 바이트와 프레이밍 여유 4,096을 사용하는 보수적 검사를 유지한다. 실제 토큰 수가 아니라 호출 전 상한 검사이며, 응답 사용량 정산은 기존 로직을 따른다.

모델이 보지 않은 기존 RPG UUID를 추측해 수정하면 `rpg_context_missing`으로 거부한다. 별칭으로 새 엔티티를 만드는 경로와 전체 게임 상태 검증은 유지한다. RPG의 200개 저장 제한은 10,000개로 조정했고, 저장량을 그대로 모델 입력량으로 사용하지 않는다. 서버는 현재 전체 RPG 상태를 읽어 정합성을 검증하므로 이 숫자가 대규모 서비스 성능 보장은 아니다.

## 기억의 정보 성격과 정체성

기존 `identity / episode / reflection / summary / world` 종류를 유지하면서 다음을 추가했다.

| 필드 | 의미 |
| --- | --- |
| `claim_type` | `interpretation`, `canon`, `npc_claim`, `mixed` |
| `importance` | 0~3. 검색 우선순위에 사용 |
| `unresolved` | 미해결 복선/쟁점. 일반 일화보다 우선 |
| `entity_ids` | 현재 선택된 인물·장소·퀘스트 등과 연결. 같은 판정의 새 alias도 가능 |
| `source_memory_ids` | 요약의 원본 등 명시적 인용. 실제 선택된 기억만 허용 |
| `reason` | 정체성 변화의 이유 등 설명 |
| `replaces_memory_id` | 같은 종류·정보 성격의 선택된 기억을 명시적으로 개정/해결 |

현실 보고는 모델이 쓰는 기억과 별도로 서버가 `reported_fact`로 표시한다. 이는 사용자가 보고한 사실이며 독립적으로 검증된 진실이라는 뜻이 아니다. 정체성과 성찰은 `interpretation`만 허용한다. `npc_claim`은 NPC 참조가 필요하다. 현재 RPG 엔티티는 정본 상태이며 요약만으로 능력치·아이템·퀘스트 상태를 덮어쓸 수 없다.

요약은 원본의 정보 성격을 그대로 유지하거나 `mixed`로 표현해야 한다. NPC 주장을 정설로 승격하는 요약은 거부한다. 원본의 높은 중요도와 미해결 표시는 요약에 상속한다. 기존 기억을 개정할 때 원문은 삭제하지 않고 비활성화하며, 선택 가능한 새 버전과 출처 연결을 남긴다. 이 일반적인 이력 보존보다 사용자의 현실 기록 삭제권이 우선한다.

GM 정체성은 모델 세션이 아니라 DB의 버전 있는 기억이다. 초기 정체성 이후 개정에는 변화 이유와 같은 판정의 성찰 또는 선택된 성찰 인용이 필요하다. 이전 정체성 ID, 원본 payload ID, 실제 읽은 기억 출처를 함께 저장한다. 예전 정체성이 비활성화되더라도 이력은 남는다. **최신 정체성이 삭제되면 예전 버전을 자동으로 되살리지 않는다.** 문맥에 `identity: erased`를 명시해 삭제된 성격 변화를 다시 추론하지 않게 한다.

이 구조는 성격·판단 철학의 기록과 개정을 지원하며, 모델 가중치 학습이나 실제 의식을 의미하지 않는다. 개정 내용의 철학적 일관성·아첨 여부는 의미 평가가 필요하다.

## 요약·성찰과 출처

기억이 누적되면 `consolidation_due`를 알려 현재 판정 안에서 유용한 요약을 제안하도록 한다. 매 사건마다 요약이나 성찰을 강제하지 않고, 별도 자기 성찰 API를 호출하지 않는다. 모델 출력의 기억 제안은 최대 5개이고 요약의 명시적 원본 인용은 최대 8개다. 기존 서버 내부 `deriveMemory`는 최대 50개 payload를 읽는 기능을 유지한다.

`memory_sources`는 실제 읽은 기억의 관계와 명시적 요약 원본을 구분한다. 기억 payload에는 실제 읽은 원본 payload ID도 보존하므로 RPG 버전·현실 보고·질문 등을 연결할 수 있다. 이 추적 목록은 문맥의 기억 본문에 반복 전송하지 않는다. 새 기억·요약·성찰·정체성은 **모델의 인용과 무관하게 실제 입력 문맥 전체의 현실 출처**를 상속한다.

출처가 많아져도 과거 현실 원문을 전부 다시 보내지 않는다. 서버의 source 목록과 버전 검사는 유지하고, 출처 확인/저장을 묶음 SQL로 처리한다. 요약을 재요약하거나 성찰을 정체성에 반영해도 이 관계가 이어진다.

기억 변경과 게임 변경은 같은 트랜잭션이다. 기억 검증이 뒤에서 실패하더라도 savepoint를 통해 앞서 적용한 RPG 변경을 함께 되돌린다. API 정산은 기존 별도 트랜잭션에 남는다. 재시도/중복 판정으로 기억·보상이 이중 확정되지 않는다.

## 삭제, 비공개 경계, 호환성

현실 기록 삭제·정정은 기존 `payload_sources` 기반 정리 경로를 이용한다. 요약·성찰·정체성 개정도 출처가 연결되어 함께 제거되고 검색에서 제외된다. 과거 원문, 비활성 버전, 진행 중 응답, 복원된 백업도 같은 삭제 정책을 적용한다. 중립 ID와 종류/버전 등 메타데이터는 남길 수 있지만 원문·성격 설명·변화 이유를 되살리지 않는다.

중요한 정설과 복선을 일반 로그보다 우선 검색하고 저장 이력을 유지하지만, 삭제된 현실 정보에 의존하면 정설이라도 제거한다. 출처는 여전히 보수적으로 상속하므로 삭제 하나가 여러 후속 기억을 제거할 수 있다.

버디 결과는 계속 `reality`, 확정된 `player_result.changes`, 공개 `fiction` 장면·대사·선택지다. 기억 본문, 검색 목록, 정체성 변화, 비공개 복선은 서비스의 공개 읽기/결과에 추가하지 않았다.

OpenAI wire는 required 필드, 닫힌 객체, 타입/enum/union과 참조를 유지한다. 프롬프트 크기를 줄이기 위해 반복되는 길이·숫자 범위·정규식 제한은 wire schema에서 생략하고 기존 Zod와 도메인 검증으로 강제한다. 형식과 의미 정확성은 다르며, 구조화 응답에도 내용상 오류가 있을 수 있다. [공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)

새 004 migration은 로컬 mock/승인된 합성 실행기의 bootstrap에 연결했다. 이번에는 새 임시 테스트 DB에만 적용했다. 이전 실험 DB를 열거나 과거 비용을 초기화하지 않았다. 기존 기록은 기본적으로 `interpretation`으로 취급하며 추측으로 정설로 승격하지 않는다.

## 합성 캠페인 검증

검증 결과: 전체 회귀 **171/171**, 최종 v2 회귀 **65/65**(장기 기억 11개 포함), 별도 로컬 PostgreSQL **7/7**, TypeScript 검사·빌드·`git diff --check` 통과. 전체 회귀 이후 출처 SQL 묶음 처리와 선택기 조회 최적화를 적용하고 v2/실제 PostgreSQL/빌드를 다시 확인했다. v2 수치는 전체 회귀의 부분집합이다.

- 최초 무관한 일화 **1,000개**, 이후 **80턴** 진행. 탄생을 포함한 GM 호출 **81회**, 추가 요약/성찰 호출 **0회**, 실제 유료 호출 **0회**.
- 공개 RPG 엔티티 **242개**, XP **80**, 세계 시간 **80**까지 확정. 기존 200개 제한을 넘는 캠페인도 진행했다.
- 같은 판정 안에서 요약 **10회**, 정체성 **9개 버전** 생성. 중간에 mock 모델 식별자를 바꿔도 DB의 정체성과 정설을 이어받았다.
- 매 턴 기존 OpenAI 설정의 정확한 요청 크기 검사에 통과했다. 최종 검증의 문맥 JSON은 **501~2,659바이트**이며 이는 헌장/schema를 제외한 크기다. 전체 요청과 여유분은 기존 입력 상한 내에서 검사했다.
- 오래된 정설과 비공개 복선을 유지하고 공개 결과에서는 숨겼다. 오래된 NPC·관련 기억 검색, 명시적 기억 ID 검색, 누락된 엔티티의 추측 수정 거부를 검증했다.
- 현실 출처 **60건**을 가진 요약을 선택해도 과거 현실 원문 60개를 전송하지 않았다. 그중 한 건 삭제 시 종속 성찰이 제거됐다.
- NPC 주장→정설 요약 거부, 기억 검증 실패 시 RPG 롤백, 정설 개정/복선 해결, 정체성 개정 근거 요구, 삭제/정정/진행 중 응답/백업 복원 보호를 검증했다.

실행 명령: `npm run test:v2:memory`, `npm run test:v2`, `npm run test:v2:postgres`, `npm test`, `npm run build`. 테스트의 OpenAI 전송은 주입한 가짜 응답이며, 장기 캠페인의 GM도 의도적으로 스크립트된 mock이다.

## 남은 제약과 실모델 평가 항목

검색은 ID/이름/문자열/연결/중요도 기반이다. 동의어·암시·한국어 형태 변화를 이해하는 의미 검색은 아니며, 중요한 기억이 많으면 일부가 생략된다. 이름을 직접 명시한 대상, 현재 상태와 정체성을 우선 확보하지만 모든 모순을 기계적으로 탐지하지는 않는다. 필수 상태 자체가 너무 크면 여전히 `required_context_limit`으로 멈춘다.

전체 RPG 정합성 검증은 서버 메모리에서 수행한다. 매우 큰 세계의 DB 검색 인덱스/조회 분할, 공개 게임 조회 페이지화, 대규모 지연 측정은 후속 성능 작업이다. 현재 합성 검증 수치를 무제한 캠페인이나 운영 동시 사용자 성능으로 해석하지 않는다.

실제 모델에서는 다음을 별도 승인된 합성 평가로 확인해야 한다.

1. 요약의 정보 손실, NPC 주장/추측의 사실 승격, 정설 모순과 미해결 복선 회수.
2. 정체성 변화의 근거·연속성, 이의 제기 뒤 아첨이나 과도한 성격 변화.
3. 관련 기억 회수 성공률과 부족한 근거에 대한 적절한 질문 빈도.
4. 공개 장면으로 비밀이나 삭제된 사실을 옮기지 않는지, 모델 교체 시 차이.
5. 확장된 wire 계약의 성공률, 토큰·지연·비용, 같은 턴의 요약이 주는 비용 대비 효과.
